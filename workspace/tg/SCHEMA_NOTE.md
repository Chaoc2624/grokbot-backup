# 发言行时间（2026-10-08 起，看板已支持）

每条发言行末尾加上**原消息的发送时间**（Asia/Shanghai，取自原始 JSON 的 `time` 字段，不要估计、不要编）：

    > 一隻北極熊：先花一萬開卡，再花一年3000維護一下 {{2026-10-08 18:31:21}}
    > 艺术家的爱也有保质期：5000只是… · 20000是… {{2026-10-08 18:25:38~18:26:37}}

- 写的是这一行**第一条**消息的时间；同一人用 ` · ` 连了几条时，可以加 `~HH:MM:SS` 写最后一条的时间。
- token 必须在行的最末尾（在 `【群标签】` 之后）。看板悬停时在该行最右边显示 HH:MM:SS，悬停提示显示完整日期时间；没有 token 的行照常显示，只是没有时间。
- 对不上（同一说话人有多条相同内容、机器人行等）就**不写**，不要猜。
- 最省事的做法：`mkfrag.py` 写完片段后、合并前运行
  `./venv/bin/python tools/addtimes.py <D> digests/<D>/hourly/<HH>.json`；
  更新 `daily.json` 后、推送前运行 `./venv/bin/python tools/addtimes.py <D> digests/<D>/daily.json`。
  这个脚本只在原始消息唯一匹配（同群、同小时段、说话人一致、原话都在同一条消息里）时才写时间，已有 token 的行不动。
- 改写 daily.json 或别的已有片段时，保留已有的 `{{…}}`。`tools/checkquotes.py` 已经会忽略这个 token。

- 排序（2026-10-09 起，用户要求）：时段里的小时段、话题都是**新→旧**（话题按最晚一条发言时间，零星消息在最后）；**话题内发言旧→新**（按本 token，没 token 的行留原位）；每个话题标题下有自动生成的 `~ 涉及商家：A · B`（看板显示为小标签）。生成端 tools/order.py 和看板渲染用同一规则，所以写的时候不用特意排；token 写准了排序才准。「🔎 网上核验」整块仍提到卡片最上面（多条核验按时间新→旧）；一天里的 6 小时时段也是新→旧。
